# ASMR-Cliper 0.6.1

Windows 本地 ASMR 自动剪辑工具。C++20 / Win32 界面，独立 Python 分析引擎。支持音频与视频输入，输出复制源编码包；模型分析只使用本地音轨副本，文件不会上传。

在剪辑任务中选择“跟随输入”“仅音频”或“视频（原编码）”。默认跟随输入：录音输出音频，视频输出带画面的成片。视频与音频共用删除区间，按视频关键帧向内收紧边界，不为了保留画面带回已删除的人声。

视频输入先由 FFmpeg 原编码提取首个音轨，校验音频包与时间戳后缓存。分析只读取独立音轨；复核时先按最终关键帧切点导出音频候选，发现说话就重剪音轨。确定可发布后，才一次性复制原视频与音频包并封装，检查最终音轨与已复核内容完全一致。完整画面解码校验仅对最终文件执行一次，视频与音频解码各限 2 线程。语音模型和声音分类仍可能使用较多 CPU / GPU，提取音轨不会消除模型推理负载。

「偏好设置 → 保留声音」新增心跳和 ASMR 道具敲击，默认与轻笑一起勾选；取消勾选后，V2 / V3 / V4 都会排除检出的对应声音。原“电子烟”选项显示为“呼气/烟雾”，原有选择继续保留。

在「运行环境 → 模型选择」分别选择语音识别和成片复核模型，选择自动保存，下一次任务生效。语音识别支持 **Whisper large-v3、Qwen3-ASR-1.7B、Whisper Turbo**；成片复核支持前两种完整模型。默认两项使用 Whisper large-v3，可以选择不同模型做交叉复核。模型切换会分开使用识别缓存，已有模型不重复下载。

V4 改用 **CLAP 音频与 ASMR 声音描述匹配 + 基础声学证据**，从连续支持的声音动作中确定提取区间。旧版要求每个短窗达到较高的通用声音标签分数，再对碎片收紧边界，容易过度删除；新版允许连续动作内证据强弱变化，遇到不支持的内容、话语或休息事件仍断开。V4 不根据目标时长放行未知内容；识别分数不是人工确认或已校准概率。

Qwen 使用独立的 PyTorch 运行环境和时间定位模型；CLAP 共用此运行环境。下载支持代理、分块续传和 SHA-256 校验。完整版 Whisper 与 Turbo 的依赖继续保留在原环境，互不覆盖。

成片复核默认开启，V4 必须开启。模型读取按最终切点导出的音轨，覆盖整个时间轴与拼接处；视频最后封装时再次核对音轨的原始包与时间映射。疑似话语会映射回原录音重剪，默认最多 3 轮。三轮后仍有疑似项，V2 / V3 保存成片并标为「待复听」；V4 不发布，保留复核记录。模型也可能把非语言声音误识别为文字，未检出不等于绝对没有人声。

## 直接使用

GitHub 一键编译并下载全部环境的 win64-nv 完整集成包，见 [构建与打包说明](docs/BUILD_WIN64_NV.md)。工作流入口为 **Actions → Build win64-nv (full portable package) → Run workflow**。

下载完整集成包并解压后，运行 `ASMR-Cliper\asmrcliper.exe`。从源码构建时，程序生成在 `bin\asmrcliper.exe`；源码仓库不包含运行环境、模型或媒体文件，首次使用需通过「运行环境」下载所需组件。

1. 在「剪辑任务」选择音频或视频、输出目录、输出类型和模式；也可以把文件拖入窗口。默认是宽松模式 V3。语音模型在「运行环境 → 模型选择」切换。
2. 在「偏好设置 → 保留声音」勾选想留下的声音并保存；「剪辑参数」设置语言、设备、静音阈值或 V2 参数。知道语言时手动指定，有助于减少口腔音被误识别为话语。
3. 首次使用或环境不完整时，进入「运行环境」检测，点击「补齐环境」。Python、分析依赖、模型和 FFmpeg 都可以下载。
4. 下载代理在「偏好设置 → 网络代理」设置，默认 `http://127.0.0.1:10886`；支持直接连接、测试下载站点、取消和重试。
5. 回到「剪辑任务」点击「开始剪辑」。完成后进入「处理记录」，播放结果或打开时间对照与结果目录；若标为「待复听」，点击「待复听位置」查看成片时间和模型疑似文字。

详细过程集中在「运行日志」。底部在任务运行时显示状态，完成或出错后保留必要结果提示。任务运行中可以切换页面。界面取消了虚线聚焦边框；选中的模式和导航使用浅绿色，键盘焦点使用轻微底色提示。

启动时只检测，不会自动下载。环境检查验证模型完整性、依赖加载、版本和 FFmpeg 启动；模型实际推理在剪辑时执行。「取消任务」结束整个后台进程组，保留有效模型和已完成的缓存。关闭窗口也会取消当前任务。模型和 FFmpeg 的未完成下载支持断点续传；Python 小型安装包重新下载，pip 管理依赖缓存。

环境安装细节与命令行入口见 [环境管理说明](docs/ENVIRONMENT.md)。

## 三种模式

| | 严格模式（V2） | 宽松模式（V3） | 提取模式（V4） |
|---|---|---|---|
| 主要取向 | 删除更大范围，优先连续长段 | 尽量保留可自然衔接的完整动作 | 只接纳连续的 ASMR 声音匹配与声学证据 |
| 说话前后 | 默认前 5 秒、后 7 秒，再找切点 | 根据声音上下文调整 | 根据声音上下文调整 |
| 密集聊天 | 允许合并删除 | 能衔接的中间 ASMR 保留 | 还需正向声音证据 |
| 未知声音 | 共同排除规则处理 | 共同排除规则处理 | 不提取 |
| 成片复核 | 默认开启，可关闭 | 默认开启，可关闭 | 必须通过 |

严格模式的四个参数集中在「偏好设置 → 剪辑参数」，只对 V2 生效。严格模式通常剪得更多，但两个模式独立选择切点，具体时长不保证单调关系。

完整提示词位于 `docs/prompts/strict-v2.txt`、`docs/prompts/relaxed-v3.txt` 和 `docs/prompts/extract-v4.txt`，也可在界面查看、复制。它们是剪辑规则说明和可复用提示词。**编辑提示词文件只改变说明文字，不会自动改变引擎行为**；算法由模式与界面参数驱动。

## 输入、输出与源编码

支持常见音频，以及 MP4 / MOV / MKV / WebM 视频。处理首个音轨与首个非封面视频轨道；多音轨文件会在日志中提示，其他音轨、字幕、附件不输出，避免保留未经分析的人声或失效的字幕时间轴。没有音轨的视频不能自动分析。

| 输出类型 | 行为 |
|---|---|
| 跟随输入（默认） | 有视频画面则输出视频，否则输出音频 |
| 仅音频 | 从音频或视频中剪出原编码音轨 |
| 视频（原编码） | 同时剪辑画面和音轨，输入必须包含视频 |

MP4 / MOV / MKV / WebM 视频尽量沿用原容器，其他容器尝试输出 MKV；AAC LC 音频输出 M4A，其他音频使用 MKA 容器保留原编码。容器扩展名不等于编码格式。已验证 H.264 / AAC、H.265 / AAC、VP9 / Opus、可变帧率及非零起始时间戳。编码、包格式或时间戳不能安全复制时会明确失败，不会自动转码。

导出不调整音量、不降噪、不添加淡化。校验所选原始包 SHA-256、包长度、编码参数、时间戳和完整解码；视频也核对原视频包。编码类型、采样率、声道、视频分辨率等保持一致。VBR 平均码率可能随保留内容变化，保留内容没有重新压缩。

视频需要完整、可独立解码的关键帧片段，切点只向已允许区间内部调整，可能比仅音频多删一些内容。音视频使用同一时间轴；音轨边界仅保留完整原包，最多会留下约一个音频包的边缘空隙，不累积成音画漂移。没有合适关键帧区间时提示改用仅音频输出。时间对照和校验报告记录实际视频切点、额外删减时长及音频边界空隙。

AAC LC 音频单独输出继续使用原来的逐帧复制（44.1 kHz 时约 23.2 毫秒一帧）；其他编码仅为模型分析建立 PCM 副本，最终输出仍复制原包。接缝附近的解码状态可能影响波形，会继续检查突变并标记建议复听的位置。

“自然”是剪辑目标，自动模型无法保证每处听感无缝。极轻声说话与非语言口腔音可能互相混淆。当前版本采用语音识别、音频分类和能量边界启发式，没有人工逐段听审；结果不承诺逐点复现之前为单个文件制作的 V2 / V3 成片。

呼气/烟雾与饮水检测依据连续气流、吸呼气、液体与杯具等声音的组合，现有模型没有专用电子烟或吞咽标签，因此报告标为「疑似休息动作」。单独呼吸、水声或噼啪声不会直接触发这类排除。仍需复听边界；这些组合也可能与其他真实 ASMR 混淆。

## 每次输出

在所选输出目录创建独立结果子目录，避免覆盖原录音或历史成片：

- `*_ASMR_v2`、`*_ASMR_v3` 或 `*_ASMR_v4`：成片，扩展名随输出类型与容器变化，如 `.mp4`、`.mkv`、`.m4a`、`.mka`。
- `剪辑时间对照.csv`：原录音与成片的时间映射。
- `人声复核.csv`：最终成片中仍需复听的疑似话语位置；无疑似项时只有表头，具体复核状态以校验报告为准。
- `剪辑说明.txt`：时长、音频参数和复听提示。
- `校验报告.json`：原帧校验、完整解码、接缝检查和 `speech_review` 成片模型复核状态。
- `剪辑计划.json`：保留区间、切点调整和舍弃理由。

只有导出和校验完成后，结果目录才会正式出现。异常终止可能留下 `.asmrclip-*.part` 临时目录，可以在确认没有任务运行时删除。

用户设置在 `config/user.json`；默认值在 `config/defaults.json`；最近 100 条完成记录在 `config/history.json`。缓存位于 `runtime/cache`，日志位于 `runtime/logs`。缓存身份包含原文件路径、大小和修改时间；改变文件或模型会重新建立相应分析。换模式和调参数可以复用音频与识别缓存。成片复核另按实际音频包内容、成片时间映射、时长、模型文件版本、语言及规则版本缓存，完全匹配时复用已完成复核。长录音缓存可能占用数 GB，可以在任务结束后按需清理。

## 编译与重建环境

需要 Visual Studio 2022 的“使用 C++ 的桌面开发”、Windows SDK、CMake 3.24+，运行引擎使用 Python 3.12，可由程序下载。

```powershell
.\scripts\build.ps1
```

编译生成 `bin\asmrcliper.exe`，并运行 GUI 与 C++ 测试；项目 Python 环境已安装时也运行引擎回归测试。程序内嵌多尺寸 ICO 图标，源文件位于 `src/app.svg`。

新电脑可以直接通过 GUI 安装环境，也可以使用脚本：

```powershell
.\scripts\setup-runtime.ps1
.\scripts\setup-runtime.ps1 -Proxy 'http://127.0.0.1:7890'
# 不使用代理
.\scripts\setup-runtime.ps1 -Direct
```

脚本与 GUI 使用相同的校验、下载和安装流程，无需事先安装 Python 或提供 FFmpeg。优先复用已有健康的项目虚拟环境，否则下载项目专用 Python 到 `runtime/python`。正常剪辑不需要网络。旧 `runtime/venv` 依赖原来的基础 Python，迁移到其他电脑后由「运行环境」重新检查并补齐。

## 项目结构

```text
src/                 C++ GUI、进程通信、取消和结果入口
engine/asmrclip/      模型选择、语音识别、ASMR 确认、边界规划、音视频原包导出
config/              默认与用户参数
docs/prompts/        V2 / V3 / V4 可复用提示词
scripts/             构建、环境安装、模型下载
tests/               规则与音视频同步回归测试、进程取消测试
third_party/         nlohmann/json 头文件与许可证
bin/                 已编译程序（不纳入源代码版本管理）
models/              本地模型（不纳入源代码版本管理）
runtime/             核心 Python、独立神经网络环境、FFmpeg、缓存及日志
```

C++ 与引擎通过 UTF-8 JSON Lines 通信。进程调用直接传递参数；环境安装通过固定 PowerShell 脚本引导，不拼接执行用户提供的 Shell 命令；Windows Job Object 用于终止整个处理进程树。扩展说明与依赖来源见 `docs/ARCHITECTURE.md`。
