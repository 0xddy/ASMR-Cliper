# 开发说明

## 0.6.16 饮水与瓶盖动作复核

`drinking.py` 在通用 AST 排除之后、音色中断检查及 V4 正向提取之前运行。原有杯具 / 液体和饮水话语规则保留，新增结果与其取并集。先在未排除的人声 / 音乐区间上使用 10 秒窗口、5 秒步长比较 CLAP 饮水、吞咽、瓶盖、ASMR、物品处理与水声描述，较宽的候选条件只用于召回；再以 3 秒窗口、1 秒步长核验候选前后上下文。删除需要饮水与吞咽同时胜过竞争声音，并具有连续多个窗口支持，或相连的开瓶在先证据。相似度不是置信概率。

瓶盖单独不触发删除。确认饮水后仅沿有证据的相连动作和最多 2 秒短停顿延伸；恢复 ASMR、缺少证据、语音 / 音乐阻断或上下文断开时停止。未知候选记为 uncertain，不生成删除区间；V4 仍需自身的正向 ASMR 证据。V2 / V3 勾选保留喝水时跳过新复核，V4 始终执行。引擎和 GUI 同步将 CLAP / neural 计入必需环境，避免缺失模型时静默漏检。

共享 `SoundMatcher` 的按需工作进程与语义缓存，新增提示描述参与缓存身份；进入语义阶段前释放 AST 模型。进度区分候选扫描和动作核对，并显示窗口完成数。候选判定及短窗证据保存到计划、校验报告 `drinking_review` 和原片分析时间轴的 `饮水复核.csv`；`drinking-review.json` 纳入成功任务的缓存清理白名单。

测试覆盖弱液体标签下的连续饮水、开瓶后吞咽、瓶盖 / 水声 / 敲瓶及口腔音保护、间断上下文、模式和保留设置、重规划、导出记录与缓存清理。真实漏检样本只保存匿名化的模型分数用于回归，不包含媒体、路径、文件名或转写。额外在本机验证用户确认的成片区间，以及其原片上下文和既有语音排除边界。

## 0.6.15 窗口重绘与闪烁修复

主窗口 `WM_PAINT` 只为脏区域建立 `BufferedSurface`，完成背景、卡片与文字绘制后一次提交；普通按钮、下拉控件、模式卡和历史行也使用缓冲绘制。开关保留自己的抗锯齿缓冲。UI 线程统一初始化 / 释放 Windows buffered paint，目标 DC 的子窗口裁剪区域保持有效；自绘按钮跳过独立擦背景阶段。

任务进度和耗时只刷新底部状态区，纯日志事件不触发页面背景重绘。环境状态仅在环境页刷新正文，隐藏页面进入时再应用最新状态。布局先计算控件位置与显示状态，再用 `DeferWindowPos` 批量提交，跳过未变化的控件，以 `SWP_NOREDRAW` 避免中途同步绘制，完成后统一使受影响区域失效。不再重复设置相同控件文字；DPI 更新先替换字体，完成布局后刷新，最小化不压缩子控件布局。通过位置批量隐藏的开关也会停止动画定时器。

`gui_rendering` 用真实窗口消息和脏区验证连续 100 条进度只影响页脚、日志不刷整页、布局中没有同步子控件绘制、最小化不移动控件，以及缓冲提交前后像素和裁剪边界。导航、下拉、缩放、动画、自动保存与任务进度继续执行原有 GUI 回归。动画反向连续性在切换函数返回时验证，避免把同步保存设置所经过的正常动画时间误判为跳变。参考 [Windows buffered paint](https://learn.microsoft.com/en-us/windows/win32/api/uxtheme/nf-uxtheme-beginbufferedpaint) 和 [批量窗口定位](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-deferwindowpos)。

## 0.6.14 视频精确切割

新增 `video_cut_mode=copy|precise`，默认 copy；GUI 的「视频（精确切割）」保存为 `output_kind=video` + `video_cut_mode=precise`，自动保存并回填。原包复制路径不变，无法保留完整 GOP 的错误提示指向精确切割选项。

`video_encode.py` 仅读取视频包的显示时间戳和帧长建立索引，每个声音保留区间向内对齐到完整视频帧。音轨先按最终映射复制 / 淡化 / 转码并复核；只有可发布时才处理画面。逐段从之前的关键帧解码参考帧，只编码被批准的帧，并验证每帧 PTS 与索引一致。输出使用同一拼接时钟，保留可变帧间隔、分辨率、像素位深、色彩参数、SAR 和 display matrix；不依赖原 GOP 边界作为切点。

H.264 或其他 8 位源使用 H.264，HEVC 或更高位深使用 HEVC；高质量有损编码（CRF / CQ 18）。自动 / CUDA 设备与兼容像素格式尝试 NVENC，编码失败后删除中间文件并回退 libx264 / libx265；显式 CPU 跳过 NVENC。解码和软件编码限制线程，进度显示已编码视频帧数。精确视频和已确认音轨以 `-c copy` 合并，逐包验证两个流的内容和时间戳，再进行最终完整解码；编码与合并中间文件由现有 staging 生命周期清理。

报告记录 `video_payload_unchanged=false`、`video_encoding`、`video_frame_trim_seconds` 和最终映射，音轨的 `payload_unchanged` 独立记录。测试覆盖无关键帧短区间、偏移时间戳、多段拼接、VFR / WebM、旋转方向、10 位 HEVC 色彩参数、FLAC 与淡化、复核拒绝时不编码画面，以及 NVENC 回退。参考 [FFmpeg 的 seek 与 streamcopy 说明](https://ffmpeg.org/ffmpeg.html)。以下版本小节保留历史实现背景。

## 0.6.13 任务缓存生命周期

`task_cache.py` 管理指纹目录及 `program-menus/<指纹>` 的分析缓存。成片通过最终导出校验并原子发布后，在节目单推理之前释放识别器、分类器、复核器和分析 WAV 的 mmap，再清理 PCM、独立音轨、帧特征、转写、语义分类、提取证据、复核重试及推理中转文件。导出目录已有剪辑计划、时间对照、复核位置和校验报告。节目单旁置文件写入成功后清理自己的窗口缓存；不再专门写一份随后立即删除的完整窗口证据。

保留 `.lock`、来源和少量 `task-state.json`，避免删除锁文件后产生并发竞争。清理在当前任务锁内执行；开始任务时以维护锁整理其他闲置缓存，逐个尝试任务锁，跳过活跃任务及本次重试目录。失败 / 取消可恢复缓存保留 7 天，闲置缓存按 8 GiB 总量、磁盘至少 2 GiB 可用空间的目标从旧到新整理；这些限制不驱逐运行中数据。旧缓存可由处理记录中的成功导出信息判定为已完成，新版本已开始重试的状态优先于旧记录。

只删除已知引擎文件，检查指纹目录、绝对路径边界及 Windows reparse point，不跟随符号链接或目录联接，保护输入和输出位置。新神经模型进程的临时目录放入所属任务缓存，强制取消后的遗留文件也纳入同一保留策略。清理失败记录日志和 `cache_cleanup`，不将已保存成片标记失败。测试覆盖实际音视频导出、V2 / V3 / V4 待复听结果、节目单、文件锁、目录联接、重试、限额和存储错误。

## 0.6.12 设置自动保存

移除页头保存按钮，保留右对齐的「恢复本类默认」。开关、声音复选框、模型 / 语言 / 设备 / 输出下拉项和 V2 / V3 / V4 选择即时保存。输入框通过独立的 400 ms 定时器合并连续输入，失焦、切换页面和关闭窗口会提交待保存项。每个输入独立验证，只更新对应配置；数值范围与启动任务共用校验规则，未完成或无效输入不会覆盖最后有效值，失焦时提示具体字段。

配置回填不触发保存；重置清除当前分类的待保存输入并原子写入默认值，其他分类保持原值。磁盘写入失败回滚内存配置并显示错误，保留待重试项。测试使用独立配置文件检查真实落盘、延迟保存、失焦 / 分类切换、非法输入隔离、重置、写入失败恢复、V4 强制复核和新实例重新读取。运行任务时保持设置锁定。

## 0.6.11 开关绘制与动画

开关行及声音复选框不再用矩形背景表示焦点。滑动开关采用 GDI+ 抗锯齿胶囊轨道和圆形滑块，整行缓冲后一次提交，避免动画闪烁。点击立即更新逻辑值，视觉位置和轨道颜色在 180 ms 内缓出；每个开关使用独立 16 ms 子窗口计时器，连续点击从当前插值位置反向切换。

配置回填、隐藏、禁用和销毁结束动画并清理计时器，系统关闭客户端动画时直接切换。声音复选框保持即时勾选。GUI 回归通过真实窗口消息和计时器检查逻辑值即时生效、中间帧、反向切换、隐藏 / 禁用 / 重置，以及 100% / 150% / 200% 缩放下抗锯齿边缘与纯白背景。

## 0.6.9 首尾淡化、输出音质与设置布局

`edge_fade_enabled` 默认 true，`edge_fade_seconds` 默认 0.5，范围 0.05–3 秒；旧配置未包含该键时使用新默认。与接缝淡化独立控制，在同一次流式音轨编码中完成，单段输出也处理。首尾长度最多为对应首 / 尾片段的四分之一和空窗上限的 45%，避免短片段淡化重叠。线性包络在第一和最后一个 PCM 采样达到零；有损编码会有编码误差。最终语音复核与节目单使用处理后的音轨。视频不施加画面滤镜，继续逐包验证画面、合并后音轨和时间戳。

报告 `audio_fades.edges` 记录实际输出位置、方向和时长，另写 `首尾淡化.csv`；`joins` 仍只记录内部接缝，不将边缘淡化当作接缝音量差。选择跟随源编码且两个开关均关闭时恢复原包输出。处理记录标记首尾 / 接缝，不将已重新编码的音轨报告为原包一致。

偏好设置采用等宽分类导航、页头保存和重置、最大 1040 逻辑像素内容宽度。停顿参数与两种淡化按行对齐，复核和节目单并列展示；V4 必选开关保持可辨识的开启状态。GUI 测试覆盖最小 / 宽窗口、独立开关和时长保存、范围验证及分类草稿。

`audio_output_codec` 为 source（默认）/ flac / pcm / aac，归于识别与成片分类。候选先用兼容源编码的临时容器保存，再在同一遍浮点 PCM 流上淡化和编码；源采样率、声道与所选编码在输出后核验。FLAC 使用 16 / 24 位整数，PCM 为 32 位浮点 WAV，启用 RF64 auto 以支持超过 4 GiB 的长录音。AAC 使用源流码率或原保留包的平均码率，无损输入使用整条音轨 320 kbps；上限按该采样率和声道约束。报告 `audio_encoding` 区分源 / 目标编码、目标码率来源、无损编码及未重采样状态，不能宣称浮点转 FLAC 位级无损或恢复有损源的丢失信息。

音频按所选编码选择 .flac / .wav / .m4a。视频使用 FLAC / PCM 或 WebM 换 AAC 时采用 MKV；中间音轨与最终容器对应，最终画面和已经复核的音轨逐包与时间戳校验。即使没有任何淡化，只要指定了输出编码，也执行转换并合并；不会错误回退到原音轨。

## 0.6.8 偏好设置分组

偏好设置收为「剪辑与声音」「识别与成片」「网络下载」三个分类。声音保留、空窗和淡化并列展示；V2 专用参数折叠。语音和复核模型与语言、设备、复核开关及节目单归在同一分类；运行环境仅管理模型文件和基础组件，通过按钮互相导航。

保留配置键和原有参数。三个读取函数分别负责分类保存，验证失败回滚整次配置变更；`populateSettings(tab)` 只回填当前分类，避免恢复默认时覆盖其他分类或输出类型的未保存输入。开始任务仍整体读取当前表单。复核模型随复核开关启用，V4 强制复核；任务期间锁定设置但允许切换分类。原 `menu` 设置截图参数指向识别分类，`sounds` / `fade` 指向剪辑分类。

现有 GUI 回归覆盖分类独立保存、恢复默认与草稿保留、验证失败回滚、严格参数展开收起、最小窗口布局、模型管理跳转及下拉菜单键盘操作。

## 0.6.7 可设置的最长空窗期

`max_pause_seconds` 默认 1.5，允许 0.3–10 秒；取代旧 `silence_seconds` 检测门槛，升级时不把旧 7 秒值迁为新上限。GUI 使用原剪辑参数页的数字控件，保存、默认恢复及任务配置共用新键。

`pauses.py` 结合 RMS 与峰值计算静音区间，不对中间的有效声响做形态学闭合。规划将获准区间投影到连续成片时钟，静音内部和跨接缝的停顿统一限长，保留两侧余量；不因为一次静音裁短而对严格模式的已批准声音动作重新施加最短片段限制。源分析帧以及模型识别缓存可复用，剪辑计划重新计算。滤镜和编码边界预留时间计入上限，较长淡化自动收紧。

视频关键帧对齐后，重新检查拼接时钟；超过静音预算时移除与多余静音相交的已批准 GOP，再检查新接缝，直到满足预算。循环每轮至少移除一个 GOP，不扩大任何允许保留区间。最终音轨在已有的拼接检查扫描中同步用 20 ms 窗口测量各声道 RMS / 峰值，避免双耳反相导致单声道抵消误判。`pause_check` 保存实测最大值及超限位置，另写 `空窗检查.csv`；不能把主观听感或模型判断宣称为绝对无空窗保证。

## 0.6.6 可选音频接缝淡化

`join_fade_enabled` 默认 false，`join_fade_seconds` 默认 0.3（每侧，允许 0.05–2）。`audio_fades.py` 在已对齐的候选音轨上按采样时钟施加线性增益包络，短片段每侧最多占该片段的四分之一。只处理实际输出接缝，不更改剪辑规划、片段顺序或映射。解码保持源采样率、声道，流式处理并交给单个 FFmpeg 进程编码；关闭或仅一段时完全绕过此路径。

滤波发生在 `Reviewer.inspect` 前。视频先准备音轨并淡化 / 复核，确认后复制原视频，再将已复核音轨原包封装；逐包核对视频和已复核音频的内容、编码参数与呈现时间，最后完整解码。编码或合并失败不发布。滤波后 `payload_unchanged=false`，记录编码信息与 `encoded_packets`，视频仍 `video_payload_unchanged=true`；不再把音轨报告成源包一致。`audio_fades.joins` 和 `接缝淡化.csv` 保存每侧时长与原接缝两側 RMS dBFS / 差值。

GUI 使用独立的音频过渡偏好页，任务期间锁定，保存 / 重置不解析其他页未完成的输入；处理记录显示淡化标记。该可选滤镜优先于旧模式提示词中默认不使用淡化的音质约束。

## 0.6.5 成片节目单

`program_menu.py` 只读取最终发布文件的音轨，位于原帧校验、完整解码校验和语音复核之后。`media_ready` 事件先将已完成媒体写入 GUI 处理记录，再开始可选的第 7 阶段；生成失败或取消不回滚媒体。最终 `complete` 更新同一条记录，避免重复。旧记录通过 `engine/main.py menu --config ...` 单独补生成，不调用剪辑规划或导出器。

按最终播放时间以 300 秒块流式解码单声道 16 kHz PCM，视频不解码画面。5 秒观察区间配最多 10 秒声音上下文，探测不跨实际导出拼接边界；处理 AAC priming、视频音轨偏移及短边界空隙，时间不来自原录音。CLAP 分别比较声音描述，正向类别接近时使用混合标签，与说话等竞争或低相似度时保留为待确认。同类相邻区间合并，复核疑似文字按最终时间叠加到对应条目。候选描述没有节目顺序语义，永不用于拼接成片。

独立节目单缓存按解码窗口 PCM、模型文件版本、提示描述和设备索引，与 V4 提取缓存及判定分离。取消后可复用已完成窗口。输出为 TXT、CSV、JSON 三个旁置文件及报告的 `program_menu` 字段，不写入音视频文件或重新封装。`generate_program_menu` 默认 true，GUI 使用独立偏好页；缺少 CLAP / neural 时剪辑仍可完成并随后补生成。

## 0.6.4 任务进度与语言确认

`progress.py` 用任务局部上下文发送 `task_progress` 事件：阶段编号 / 标题、当前复核轮次 / 最大轮次、音频块、检查步骤和窗口计数。复核百分比按本轮实际块及两组窗口覆盖计算；下一轮单独计数，通过则提前结束。进度表示工作覆盖，不估算剩余时间。普通模型日志不覆盖 GUI 的阶段信息。Whisper 以已越过的窗口边界计数，不把转写句子数量当成窗口数量；Qwen 子进程逐窗报告数值，由父进程补上阶段和轮次。

GUI 通过单独的 1 秒定时器及单调时钟显示任务耗时，启动时重置，完成、失败或取消后冻结；处理记录保存 `elapsed_seconds`，与成片 `duration` 区分。等待语言确认的时间计入任务总耗时。

GUI 自动语言任务携带 `confirm_detected_language=true`。引擎识别语言后发送 `language_confirmation` 并等待标准输入中的 `language_confirmed` JSON；弹窗允许确认、改选或取消。未知语言必须明确选择。手动语言及默认 CLI 任务不等待交互。用户修改语言后，使用所确认语言的转写缓存标识，后续声学处理与成片复核沿用该语言；不会复用错误语言的转写。`ProcessRunner` 输入管道只传递短控制消息，取消仍结束整个进程树。

## 0.6.3 音色突降过渡检查

V2 / V3 / V4 共用 `transitions.py`。在已有 16 kHz 分析副本上，以 0.25 秒块计算高频能量占比和频谱质心，寻找相对前文突然变闷、持续短时间又恢复的候选。当前启发式要求高频占比下降约 7 dB、质心下降到约 60%，并寻找约 1.25–20 秒内的恢复；这些是筛选参数，不是固定删除余量。单纯音量下降、原本稳定的低频声音、瞬时变化或没有恢复的段落不自动判为中断。频谱结果单独缓存，不重建已有 PCM 和语音缓存；128 块批量计算限制临时内存。

每个候选分别检查前后 4 秒和内部 2 秒窗口（1 秒步长，短段使用实际时长），内部窗口不借用后续 ASMR。基础声学证据已否定“纯背景残留”的候选直接保留或记为未确认；其余调用本地 CLAP 声音模型。只有前后达到现有 ASMR 正向匹配条件、内部每个窗口均明显匹配背景残留且没有有效声音动作证据时，才产生 `transitions` 删除区间。低频口腔音、心跳、道具敲击和轻笑等动作证据会阻止这项删除。未知内容不因为“频率低”就删除；V4 仍受原有正向提取规则约束。

`selected_exclusions` 在所有模式及复核后的重新规划中始终应用确认区间，切点继续交给现有自然边界策略，导出仍复制源包。源采样率、码率或播放速度未被修改。`transition-review.json` 缓存诊断、成片 `校验报告.json` 的 `transition_review` 和 `过渡复核.csv` 记录候选位置、模型证据与判定；位置采用原片分析时间轴。

此项在 V2 / V3 中使用已安装的 CLAP 和独立模型运行环境。缺失时明确记录 `needs_model`，不擅自删除未确认候选；可在运行环境下载“ASMR 声音识别 · CLAP”及其依赖。V4 本来就要求这些组件。声音匹配与 V4 共用一个按需加载的工作进程及原有语义缓存，稀疏窗口拼成紧凑样本，避免为了几个远隔片段分配整段 PCM。

回归覆盖频谱候选范围、低频/音量变化保护、内部探测覆盖、缺失模型、未知声音、三种模式及重新规划、缓存失效和稀疏样本一致性。一次约 4.28 小时实际分析音轨的频谱扫描与候选搜索约 6.2 秒，声音模型确认另外计时；在 CPU 上抽查两个候选，均因证据不足而未删除。尚未取得用户所述具体位置，不能据此宣称已验证该现象的实际漏删修复，也不能由音色变化断言主播确实发生了中断。

## 0.6.2 特征计算与重试缓存

`acoustic_features.py` 将 AST 的逐帧 Python 特征循环改为 NumPy 批量运算。仍使用 400 样本帧、160 样本步长、512 点 FFT、逐帧去直流、0.97 预加重、原窗函数和 Mel 滤波器；保留 float64 计算、complex64 FFT 结果舍入和 float32 对数输出的顺序。仅提前截断模型最终不会使用的第 1024 帧之后的特征，不改变分析窗口与静音判定。新旧特征的回归比较使用安装的 Transformers 参考实现，不依赖下载模型。

AST 缓存全命中时不重写 JSON，也不初始化推理会话；每完成 160 个新窗口及每次扫描结束时原子保存，取消后最多重算上一个检查点之后的部分。现有有效缓存继续可用。Whisper / Qwen 延迟到实际推理或语言检测时才加载，完整语音缓存命中后不再占用模型加载时间和显存。

成片复核保留原来的整个时间轴、额外边界窗口和相邻 300 秒分块间的 2 秒重叠。每个分块的两个覆盖阶段均完成后，才在 `review-results/chunks` 原子保存局部疑似话语与检查窗口数。缓存身份包括模型/定位模型版本、语言、设备选项、规则版本、实际解码 PCM 的 SHA-256、样本数和窗口定义。重剪后只有内容完全相同的块可复用；结果按新成片中的位置重新映射。没有以原录音区间代替实际切口解码，也没有通过跳过复核来加速。

本机 RTX 4070 Ti 上，真实录音抽取的 192 个窗口按旧/新实现交替测试三轮，包含特征、GPU 推理和缓存写入、共用已预热模型，中位耗时 5.81 / 4.73 秒，约减少 19%；分类记录完全一致。此为声学窗口阶段的小样本测量，不是整段剪辑的加速比例。45 秒真实音轨的完整 Whisper large-v3 复核结果与覆盖数一致；断点恢复另有回归测试。

## 0.6.1 视频音轨预处理与延迟封装

`audio_source.py` 为视频输入调用 FFmpeg 的 `-copyts -map 0:a:0 -c:a copy -vn`，提取与原容器同类的独立音轨；不使用提取后的音频重新编码最终成片。提取后逐包校验编码参数、字节内容、包数量和时间戳，拒绝失去映射关系的结果，再原子发布缓存和校验记录。语音识别与分类仅读取从该音轨生成的 PCM。旧的完整 PCM 分析缓存继续复用。

视频导出先索引完整 GOP，并把声音分析区间向允许范围内的关键帧收紧。此索引在一次任务内跨复核轮次复用。每轮先按最终区间复制音轨、执行完整语音复核；被拒绝的候选不复制画面，也不进行整段视频解码。可发布时，`copy_media_packets` 按相同区间一次性复制并封装原视频、音频包，`verify_reviewed_audio` 要求最终音轨的 SHA-256、包数量和时间映射与复核候选完全一致。

最终文件保留原有的逐包、时间戳、接缝与完整解码校验。完整 FFmpeg 解码移到复核之后，只执行一次，视频/音频解码各限 2 线程、滤镜线程限 1。日志区分提取音轨、音轨复核、视频封装与最终解码；`decode_validation` 和 `audio_review_before_video_export` 记录验证范围。模型推理资源策略保持原有设置。

参考：[FFmpeg streamcopy 与时间戳选项](https://ffmpeg.org/ffmpeg.html)。以下按版本分节的说明保留历史实现背景，以本节的当前视频流水线为准。

`src/MainWindow.cpp` 管理事件、任务调度、文件选择、配置、记录和提示词窗口；`src/MainWindowPages.cpp` 管理五页导航、布局和绘制；`src/UiControls.cpp` 管理下拉选择和开关状态，`src/UiTheme.h` 统一色彩。控件按页面与任务状态显示，底部进度只在工作期间出现。`ProcessRunner` 使用 `CreateProcessW` 启动隐藏的 Python 或 PowerShell 工作进程，并通过管道读取 UTF-8 JSON Lines；Job Object 负责取消整个子进程树。UI 线程通过窗口消息接收事件，不在后台线程直接修改控件。

单行编辑控件以实际 `TEXTMETRIC.tmHeight` 为高度，置于 40 逻辑像素的公共外框中垂直居中，左右各留 12 逻辑像素；框内留白处的点击转发给编辑控件。下拉选择沿用 `CB_*` 读写接口，点击、空格或方向键打开原生菜单；当前选项也写入窗口标题，便于读取控件名称。开关以 `BM_GETCHECK/BM_SETCHECK` 读写，点击或空格切换；禁用时阻止操作。

应用标题和版本资源为 ASMR-Cliper 0.4.0，CMake 的输出名为 `asmrcliper`。`src/app.ico` 含 16–256 像素七种尺寸，由 `src/app.svg` 所描述的耳机与声波图形生成；项目目录和引擎模块名保持兼容。

引擎入口：

```powershell
.\runtime\venv\Scripts\python.exe -X utf8 .\engine\main.py run --config .\runtime\jobs\example.json
.\runtime\venv\Scripts\python.exe -X utf8 .\engine\main.py doctor --config .\config\defaults.json
```

任务配置最少包含 `input`、`output_dir`、`mode`（`strict` / `relaxed` / `extract`）。其余字段继承 `config/defaults.json`。`language` 支持 `auto/ko/ja/zh/en`；`device` 支持 `auto/cuda/cpu`。所有路径使用 Unicode。

「保留声音」为独立设置页，复选框置于文字左侧，`true` 表示保留。五个布尔配置为 `keep_soft_laugh`（默认 true）、`keep_loud_laugh`、`keep_vaping`、`keep_drinking`、`keep_impacts`（后四项默认 false）。没有保留说话声配置；语音识别和情绪话语检查始终生效。页面单独保存和重置，不受其他页未完成输入影响。

AST 分类缓存版本为 `events-v4`，缓存保存类别证据，不包含保留/删除决定。`selected_exclusions` 每次规划都读取当前配置，复查后重新规划也如此。轻笑子类与一般 Laughter、大笑分别记录；有笑声证据时不把一般 Speech 标签直接升级为说话，但具体话语类别、实际转写词和情绪发声仍优先删除。未识别出轻笑子类的一般笑声按大笑类处理，属于需实际样本继续校准的边界。掉落/撞击类需同时出现相对局部背景的孤立短促突变；普通 Tap、Knock、Crackle 或音量本身不能触发这类排除。

处理阶段：

1. PyAV 解码首个音轨；AAC LC 保留逐包映射，其他编码建立等长 PCM 分析网格，一次生成 16 kHz 单声道分析副本、每帧能量与源包序号。分析副本不用于最终导出。
2. 所选的 Whisper large-v3、Qwen3-ASR 或 Turbo 做 VAD 辅助识别与连续覆盖识别。按模型提供的证据过滤非语言音节与常见幻觉；支持中断后的识别窗口恢复。
3. AST AudioSet 分类器识别音乐与边界附近的非语言声学上下文。没有写死某条录音的语言或活动时间段。
4. 两种模式先共用 `exclusions.py`：候选区间内部按 6 秒上下文、2 秒步长检查人声和休息动作，再用短窗定位强人声；带情绪的短句结合转写与声学证据处理。人声分数不会被同时出现的口腔音抵消。电子烟使用重复气流与吸呼气组合；饮水使用杯具与液体/口腔动作组合，或明确饮水话语加液体声音。休息动作跟随相邻停顿与活动外扩，遇到恢复的 ASMR 或缺乏证据时停止。分类标签组合只能判断疑似活动，不能识别具体设备。
5. 严格模式合并话语与密集聊天，并应用固定默认余量；宽松模式逐段检查动作边界，没有固定前后秒数或因密度直接整段删除的规则。找不到近处停顿时扩大搜索，再决定是否舍弃。两者均禁止重新保留已排除的话语或未勾选类别区间。勾选的声音若与说话重叠或无法自然衔接，仍可能随上下文舍弃。
6. 兼容旧版 `audit` 的可选初筛复查（默认关闭），在内存中检查候选计划并映射新证据；独立的完整版模型复核在导出实际成片后执行。
7. 按原 AAC 包序号复制帧并重建时间戳；用必要的隐藏预滚帧初始化首段解码状态。源容器时间戳取整漂移不会累积进分析时间轴。
8. 校验原压缩包、解码与接缝，并对实际成片进行完整版模型复核；按后文规则重剪或标记待复听，写入映射和报告，再将临时结果目录原子改名为正式目录。

边界选择使用能量和声学分类启发式。“完整动作”与“听者预期”不能仅凭波形作绝对判定。声学分类窗口、语音概率与停顿阈值都可能需要针对新的 ASMR 类型校准。应优先增加有代表性的实际录音回归样本，而不是只追求某一个文件的保留分钟数。

## 0.4 正向提取和成片复核

模式值增加 `extract`。`extraction.py` 从同一套已缓存声学窗口筛选连续正向纹理证据，拒绝未知声音、单次命中和竞争性人声/音乐/气流/饮水/撞击证据。V4 的保留范围限制在重复证据的交集内，再使用上下文边界规划；用户勾选保留的休息声音不成为提取目标。判定标准是保守启发式，不是语义 ASMR 的已校准概率。

`review_enabled` 默认 true，V4 忽略关闭请求。`review_model` 指向独立的 `models/whisper-review`；环境管理器下载并按固定版本和 SHA-256 校验 Systran/faster-whisper-large-v3。原来的 `audit` 仍作为兼容性配置支持初筛模型的计划复查，默认 false，界面开关现在控制实际成片复核。

导出器先在任务临时目录复制 AAC 原帧并验证解码，再由 `Reviewer.inspect` 读取实际候选成片。模型按全时间轴覆盖识别，28 秒窗口边界另做 8 秒上下文复核，批次边界有 2 秒重叠；不会只扫描 VAD 命中的部分。清晰转写通过词概率、非语言音节与常见幻觉过滤后，作为剩余话语证据。`output_to_source` 使用原规划帧时钟映射跨接缝候选到源音频，两侧分别处理。

前几轮检出疑似话语时，导出器抛出 `SpeechRemaining`，临时候选不发布；流水线添加删除证据并重新规划。最多 `review_max_passes` 轮（默认 3，允许 1–5）。最后一轮仍有疑似项时，V2 / V3 / V4 都发布成片并标为 `needs_review`；若再剪会导致无可保留片段，则发布上一个有效候选，复用其完整成片复核缓存。GUI 将其保存到处理记录，显示数量并提供「待复听位置」弹窗，列出成片时间及识别文字；结果目录另存 `人声复核.csv`。这类结果不标记为失败或复核通过，模型异常和媒体校验错误仍中止。每个发布的已复核结果，其 `speech_review.candidate_payload_sha256` 对应最终音频包校验值。

`review-results` 缓存以 `full-review-2` 规则版本、实际 AAC 包 SHA-256、解码时长、采样率、声道、语言和模型路径 / 文件大小 / 修改时间生成键。只写入完整推理结果；重试时必须匹配键才能复用。调整推理参数或话语接纳规则时应递增缓存规则版本。缓存中保留原始 `speech_found` / `passed` 推理结果，发布时的 `needs_review` 不改变缓存判定。

本版成片复核为本地 Whisper large-v3；Qwen3-ASR-1.7B 尚未接入。公开多语言基准不能证明 ASMR 场景的准确率，应使用同一份标注样本比较漏删、误删与耗时。


## 0.5 可选择语音模型与 V4 修正

`model_catalog.py` 集中定义语音模型 ID、存储路径和当前必需组件。Whisper 使用原 CTranslate2 环境；Qwen / CLAP 通过 `NeuralClient` 在独立 Python 子进程中运行，采用 JSON 协议和任务临时 NPY 文件交换数据。没有 Shell 命令拼接。子进程属于 GUI 的 Windows Job Object，取消会终止整个任务树。模型阶段结束即释放进程 / GPU 模型，避免 ASR、声学分析、CLAP 与成片复核同时占用显存。

Qwen 返回真实时间定位结果，不伪造 Whisper 的词概率或对数置信度；其接纳规则使用有效词语、非语言过滤和真实对齐区间。完整成片复核仍扫描实际候选文件；初筛和复核即使选同一个完整模型，也不复用初筛转写。复核缓存版本为 `full-review-3`，包含所选模型、定位模型版本及实际音频内容。

V4 使用 `semantic.confirm` 生成正向区间。CLAP 对同一窗口比较口腔音、表面动作、说话、休息和其他声音描述，再结合 AST 纹理与独立人声否决；连续段必须有多个明确命中，允许中间存在较弱但仍支持 ASMR 的窗口。相邻窗口只承担其中心区间，避免跨过被拒绝的窗口；后续规划仍排除已识别的话语、休息、突兀撞击与长静音。证据记录在 `extraction-evidence.json`，报告保存所用模型与阶段性证据。CLAP 是音频文本匹配模型，不能保证语义活动或主观听感绝对正确。

原 `extraction.py` 保留旧版纹理候选的诊断功能，现行 V4 不以它作为最终提取依据。旧的 0.4 描述仅记录该版本行为。


## 0.5.1 心跳与道具敲击

新增 `keep_heartbeat` 和 `keep_tapping`，默认 true。AST 使用 `Heart sounds, heartbeat`、`Tap`、`Knock` 标签；连续重复证据生成类别区间，取消勾选时由三个模式的规划器排除。普通敲击与物品掉落 / 孤立撞击仍分开判断，保留选项不会覆盖话语或已识别事故排除。

V4 为心跳与道具敲击增加独立 CLAP 描述，仍需连续正向证据；关闭的类别从提取目标转为竞争类别，并屏蔽已检出的区间。声学缓存升级为 `events-v5`，防止旧缓存缺少新字段而漏删；语音识别缓存仍可复用。原 `keep_vaping` 配置键兼容保留，界面名称为“呼气/烟雾”，不扩大为删除一切普通短呼吸。


## 0.6.0 音视频输入与原编码输出

`output_kind` 为 `auto`（默认）、`audio`、`video`，GUI 选择、保存与任务配置一致。`media.inspect_media` 忽略封面图轨道，选择首个音轨与首个视频轨道。非 AAC 音轨通过 `analyze_decoded` 转为本地 PCM 分析网格，分析副本不用于编码输出。

`media.video_groups` 按解码顺序建立 GOP 索引，并验证组内画面的呈现范围。`align_video` 仅保留原计划区间内的完整 GOP，丢弃跨边界的前导/尾部画面。输出同时保留两轨的源相对时间，每段统一平移，保留 PTS/DTS 的重排关系；音频仅复制完整包。MP4 使用微秒级 movie timescale，避免 edit list 默认毫秒精度造成音轨偏移；Matroska 的 DTS 由解码器重建，逐包核对其存储的 PTS 与单调解码顺序。

导出分别计算音视频原包 SHA-256、包长列表、编码参数与实际时间戳，随后完整解码。输出报告包含 `media_kind`、`video_payload_unchanged`、`video_codec`、`keyframe_trim_seconds`、`max_audio_boundary_gap` 与实际 `mapping`。MP4/MOV 的失效 timecode 轨道不自动生成。流模板继续保留方向等流信息，旋转视频已做实际读取检查。

视频复核按真实音轨时间戳解码（为包边界空隙补分析静音，不编码新音频），缓存身份加入实际映射。`mapped_output_to_source` 用导出后的 `analysis_start` 与 `output_start/end` 映射剩余话语，避免拿关键帧调整前的音频计划返算。复核失败仍走原有重剪与原子发布流程。

媒体回归覆盖 H.264 B 帧、H.265、VP9/Opus、可变帧率、偏移时间戳、视频转纯音频、MP3 原编码音频、无关键帧失败、无画面错误，以及以模型桩跑完整 V4 视频复核与重规划。画面测试比较解码后的源/成片图像哈希，确保没有保留已删除区间的画面。
